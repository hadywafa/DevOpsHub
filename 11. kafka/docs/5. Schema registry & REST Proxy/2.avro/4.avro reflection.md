# Avro Reflection

**Avro Reflection** lets Avro serialize an ordinary Java POJO without:

- writing an `.avsc` schema manually;
- generating a `SpecificRecord` class;
- building a `GenericRecord`.

![[Pasted image 20260730172007.png]]

From a .NET perspective, it is similar to serializing a normal C# POCO: the library inspects the class fields at runtime and derives the data structure automatically.

```text
Java POJO
   ↓ Java reflection
Avro derives schema
   ↓
Avro binary data
```

Apache Avro provides `ReflectData`, `ReflectDatumWriter`, and `ReflectDatumReader` for this purpose. ([Apache Avro](https://avro.apache.org/docs/1.12.0/api/java/org/apache/avro/reflect/ReflectDatumWriter.html?utm_source=chatgpt.com 'ReflectDatumWriter (Apache Avro Java 1.12.0 API)'))

---

## 1. Maven dependency

```xml
<dependency>
    <groupId>org.apache.avro</groupId>
    <artifactId>avro</artifactId>
    <version>1.12.0</version>
</dependency>
```

No `avro-maven-plugin` is needed because no Java class is generated.

---

## 2. Create a normal Java POJO

```java
package com.example.events;

public class OrderCreated {

    public String orderId;
    public double amount;

    // Required when Avro reconstructs the object
    public OrderCreated() {
    }

    public OrderCreated(String orderId, double amount) {
        this.orderId = orderId;
        this.amount = amount;
    }
}
```

This is just a regular class—not `GenericRecord` or `SpecificRecord`.

---

## 3. Avro generates the schema at runtime

```java
import org.apache.avro.Schema;
import org.apache.avro.reflect.ReflectData;

Schema schema =
        ReflectData.get().getSchema(OrderCreated.class);

System.out.println(schema.toString(true));
```

Avro derives approximately:

```json
{
  "type": "record",
  "name": "OrderCreated",
  "namespace": "com.example.events",
  "fields": [
    {"name": "orderId", "type": "string"},
    {"name": "amount", "type": "double"}
  ]
}
```

---

## 4. Serialize the POJO

```java
OrderCreated order =
        new OrderCreated("ORD-1001", 250.0);

ReflectDatumWriter<OrderCreated> writer =
        new ReflectDatumWriter<>(OrderCreated.class);
```

The writer inspects the object and converts it into Avro binary according to the generated schema.

On the consumer side, `ReflectDatumReader` performs the opposite operation:

```text
Avro bytes
   ↓
ReflectDatumReader
   ↓
OrderCreated Java object
```

Confluent also supplies reflection-aware serializers and deserializers that use the normal Schema Registry wire format:

```text
Magic byte + Schema ID + Avro payload
```

Null fields can be enabled with `avro.reflection.allow.null=true`; its default is false. ([Confluent Documentation](https://docs.confluent.io/platform/current/schema-registry/fundamentals/serdes-develop/serdes-avro.html 'Apache Avro for Kafka | Serialization, Schema, KafkaAvroSerializer | Confluent Documentation'))

# Reflection vs Generic vs Specific

| Approach   | Java representation                         |
| ---------- | ------------------------------------------- |
| Generic    | `GenericRecord` with `put("amount", 250.0)` |
| Specific   | Class generated from `.avsc`                |
| Reflection | Your existing normal POJO                   |

```text
Generic    → schema exists, class does not
Specific   → schema first, generated class
Reflection → class first, schema generated at runtime
```

## When Reflection is useful

Use it when you already have Java POJOs and need quick Avro integration without code generation.

For important event contracts shared between Java, .NET, and other teams, **SpecificRecord with an explicitly designed `.avsc` schema is usually safer**. Reflection can accidentally change the schema when someone renames a Java field or modifies the class.
