# GenericRecord vs SpecificRecord in Java

Both produce the **same Avro message format**:

```text
Schema ID + Avro binary payload
```

The difference is how your Java application represents the record.

For a .NET developer:

```text
GenericRecord  ≈ Dictionary<string, object> / dynamic object
SpecificRecord ≈ Generated strongly typed C# class
```

Apache Avro recommends `SpecificRecord` when the schema is known at compile time, and `GenericRecord` for dynamic schemas discovered at runtime. ([Apache Avro](https://avro.apache.org/docs/1.12.0/api/java/org/apache/avro/generic/package-summary.html?utm_source=chatgpt.com "org.apache.avro.generic (Apache Avro Java 1.12.0 API)"))

---

## Common Avro schema

Create:

```text
src/main/avro/OrderCreated.avsc
```

```json
{
  "type": "record",
  "namespace": "com.example.events",
  "name": "OrderCreated",
  "fields": [
    { "name": "orderId", "type": "string" },
    { "name": "amount", "type": "double" },
    {
      "name": "currency",
      "type": "string",
      "default": "AED"
    }
  ]
}
```

## 1. GenericRecord

With `GenericRecord`, no Java class is generated.

You load the schema and set values using field names:

```java
Schema schema = new Schema.Parser()
			        .parse(new File("src/main/avro/OrderCreated.avsc"));

GenericRecord order = new GenericData.Record(schema);

order.put("orderId", "ORD-1001");
order.put("amount", 250.0);
order.put("currency", "AED");
```

Producing it:

```java
Properties props = new Properties();

props.put("bootstrap.servers", "localhost:9092");
props.put("schema.registry.url", "http://localhost:8081");
props.put("key.serializer",
		  "org.apache.kafka.common.serialization.StringSerializer");
props.put("value.serializer",
          "io.confluent.kafka.serializers.KafkaAvroSerializer");

try (KafkaProducer<String, GenericRecord> producer = new KafkaProducer<>(props)) {
    producer.send(
        new ProducerRecord<>("orders", order.get("orderId").toString(), order)
    ).get();
}
```

Reading values from a Generic consumer:

```java
GenericRecord order = record.value();

String orderId = order.get("orderId").toString();
double amount = (Double) order.get("amount");
```

### Main disadvantage

There is no compile-time field checking:

```java
order.put("amunt", 250.0); // Typo compiles
```

It fails only at runtime because `amunt` is not in the schema.

Use `GenericRecord` for generic tools, schema explorers, connectors, migration utilities, or applications that process many unknown event types. ([Apache Avro](https://avro.apache.org/docs/1.12.0/getting-started-java/?utm_source=chatgpt.com "Getting Started (Java) | Apache Avro"))

## 2. SpecificRecord

With `SpecificRecord`, Maven generates a strongly typed Java class from the `.avsc` schema.

### Maven configuration

```xml
<properties>
    <maven.compiler.release>17</maven.compiler.release>
    <avro.version>1.12.0</avro.version>
    <confluent.version>YOUR_CONFLUENT_VERSION</confluent.version>
</properties>

<repositories>
    <repository>
        <id>confluent</id>
        <url>https://packages.confluent.io/maven/</url>
    </repository>
</repositories>

<dependencies>
    <dependency>
        <groupId>org.apache.avro</groupId>
        <artifactId>avro</artifactId>
        <version>${avro.version}</version>
    </dependency>

    <dependency>
        <groupId>io.confluent</groupId>
        <artifactId>kafka-avro-serializer</artifactId>
        <version>${confluent.version}</version>
    </dependency>
</dependencies>

<build>
    <plugins>
        <plugin>
            <groupId>org.apache.avro</groupId>
            <artifactId>avro-maven-plugin</artifactId>
            <version>${avro.version}</version>

            <executions>
                <execution>
                    <phase>generate-sources</phase>
                    <goals>
                        <goal>schema</goal>
                    </goals>
                </execution>
            </executions>
        </plugin>
    </plugins>
</build>
```

Run:

```bash
mvn clean compile
```

Maven generates approximately:

```text
target/generated-sources/avro/com/example/events/OrderCreated.java
```

The Avro Maven plugin performs this schema-to-Java code generation during the Maven build. ([Apache Avro](https://avro.apache.org/docs/1.12.0/getting-started-java/?utm_source=chatgpt.com "Getting Started (Java) | Apache Avro"))

### Creating the strongly typed object

```java
OrderCreated order = OrderCreated.newBuilder()
        .setOrderId("ORD-1001")
        .setAmount(250.0)
        .setCurrency("AED")
        .build();
```

Producing it:

```java
try (KafkaProducer<String, OrderCreated> producer =
             new KafkaProducer<>(props)) {

    producer.send(
        new ProducerRecord<>("orders", order.getOrderId().toString(), order)
    ).get();
}
```

Now Java catches mistakes earlier:

```java
order.getAmount();      // Valid
order.getAmunt();       // Compilation error
order.setAmount("250"); // Compilation error
```

This is similar to using a generated C# model:

```csharp
var order = new OrderCreated
{
    OrderId = "ORD-1001",
    Amount = 250.0,
    Currency = "AED"
};
```

### Consuming SpecificRecord

By default, `KafkaAvroDeserializer` commonly returns `GenericRecord`.

To receive the generated `OrderCreated` class, enable:

```java
props.put("specific.avro.reader", true);
```

Then:

```java
KafkaConsumer<String, OrderCreated> consumer =
        new KafkaConsumer<>(props);

consumer.subscribe(List.of("orders"));

for (ConsumerRecord<String, OrderCreated> record :
        consumer.poll(Duration.ofSeconds(1))) {

    OrderCreated order = record.value();

    System.out.println(order.getOrderId());
    System.out.println(order.getAmount());
}
```

Confluent documents `specific.avro.reader=true` as the switch that makes the deserializer return generated SpecificRecord classes rather than generic records. ([Confluent Documentation](https://docs.confluent.io/platform/current/schema-registry/schema_registry_onprem_tutorial.html?utm_source=chatgpt.com "Tutorial: Use Schema Registry on Confluent Platform to Implement Schemas for a Client Application | Confluent Documentation"))

## Which one should you use?

|GenericRecord|SpecificRecord|
|---|---|
|No generated Java class|Maven generates Java classes|
|Access using `get()` and `put()`|Getters, setters and builder|
|Errors often appear at runtime|Many errors caught during compilation|
|Good for dynamic schemas|Good for known application events|
|Similar to `Dictionary<string, object>`|Similar to a generated C# DTO|

For normal microservices with known events such as `OrderCreated`, use **SpecificRecord**.

For generic Kafka utilities that must process unknown schemas, use **GenericRecord**.
