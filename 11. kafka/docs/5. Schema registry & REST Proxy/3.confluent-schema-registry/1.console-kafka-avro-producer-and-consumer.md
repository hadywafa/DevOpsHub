# `kafka-avro-console-producer` and `consumer`

These are **Confluent CLI tools** for quickly testing Kafka with Avro and Schema Registry.

```text
Terminal JSON
    ↓
kafka-avro-console-producer
    ↓ converts JSON to Avro
Schema ID + Avro binary
    ↓
Kafka
    ↓
kafka-avro-console-consumer
    ↓ converts Avro back to JSON
Terminal output
```

Although you type and see JSON, the data stored in Kafka is **Avro binary**, not plain JSON. ([Confluent Documentation](https://docs.confluent.io/platform/current/schema-registry/fundamentals/serdes-develop/serdes-avro.html?utm_source=chatgpt.com 'Apache Avro for Kafka | Serialization, Schema, KafkaAvroSerializer | Confluent Documentation'))

---

## 1. Start an Avro producer

```bash
kafka-avro-console-producer \
  --bootstrap-server localhost:9092 \
  --topic orders-avro \
  --property schema.registry.url=http://localhost:8081 \
  --property value.schema='{
    "type": "record",
    "name": "OrderCreated",
    "namespace": "com.example.orders",
    "fields": [
      {"name": "orderId", "type": "string"},
      {"name": "amount", "type": "double"},
      {"name": "currency", "type": "string", "default": "AED"}
    ]
  }'
```

The command waits on a blank line. Enter one JSON record per line:

```json
{"orderId":"ORD-1001","amount":250.0,"currency":"AED"}
```

Then another:

```json
{"orderId":"ORD-1002","amount":400.0,"currency":"USD"}
```

Internally, the producer:

```text
1. Reads your JSON.
2. Validates it against value.schema.
3. Registers or finds the schema in Schema Registry.
4. Receives a schema ID.
5. Converts JSON into Avro binary.
6. Sends magic byte + schema ID + Avro payload to Kafka.
```

With the default naming strategy, the schema is registered under:

```text
orders-avro-value
```

## 2. Start an Avro consumer

Open another terminal:

```bash
kafka-avro-console-consumer \
  --bootstrap-server localhost:9092 \
  --topic orders-avro \
  --from-beginning \
  --property schema.registry.url=http://localhost:8081
```

Output:

```json
{"orderId":"ORD-1001","amount":250.0,"currency":"AED"}
{"orderId":"ORD-1002","amount":400.0,"currency":"USD"}
```

Internally, the consumer:

```text
1. Receives raw bytes from Kafka.
2. Uses the Avro deserializer.
3. Reads the schema ID from the message.
4. Retrieves the schema from Schema Registry.
5. Caches the schema.
6. Decodes the Avro binary.
7. Prints the result as JSON.
```

The consumer does not need you to provide the schema manually because the message contains its Schema Registry ID. ([Confluent Documentation](https://docs.confluent.io/platform/current/schema-registry/fundamentals/serdes-develop/serdes-avro.html?utm_source=chatgpt.com 'Apache Avro for Kafka | Serialization, Schema, KafkaAvroSerializer | Confluent Documentation'))

## What happens with invalid input?

The schema expects:

```text
amount → double
```

This is valid:

```json
{"orderId":"ORD-1003","amount":150.0,"currency":"AED"}
```

This is invalid:

```json
{"orderId":"ORD-1003","amount":"150 AED","currency":"AED"}
```

The console producer fails during Avro serialization because `"150 AED"` cannot be encoded as a `double`.

```text
Bad JSON value
    ↓
Avro serializer rejects it
    ↓
Record is not successfully sent
```

Kafka itself does not normally perform this field-level validation.

## Schema evolution example

Start another producer for the same topic with a new optional field:

```bash
kafka-avro-console-producer \
  --bootstrap-server localhost:9092 \
  --topic orders-avro \
  --property schema.registry.url=http://localhost:8081 \
  --property value.schema='{
    "type": "record",
    "name": "OrderCreated",
    "namespace": "com.example.orders",
    "fields": [
      {"name": "orderId", "type": "string"},
      {"name": "amount", "type": "double"},
      {"name": "currency", "type": "string", "default": "AED"},
      {"name": "customerId", "type": ["null","string"], "default": null}
    ]
  }'
```

Produce:

```json
{"orderId":"ORD-1004","amount":700.0,"currency":"AED","customerId":"C-50"}
```

Schema Registry checks the new schema against the previous version. Because `customerId` has a default value of `null`, the change can remain backward-compatible.

The existing consumer can continue reading both old and new messages. Schema Registry uses compatibility rules such as `BACKWARD`, which is the default. ([Confluent Documentation](https://docs.confluent.io/platform/current/schema-registry/fundamentals/serdes-develop/serdes-avro.html?utm_source=chatgpt.com 'Apache Avro for Kafka | Serialization, Schema, KafkaAvroSerializer | Confluent Documentation'))

## Compared with normal Kafka console tools

```text
kafka-console-producer
    → normally sends strings or raw bytes
    → does not automatically use Schema Registry

kafka-avro-console-producer
    → accepts JSON input
    → validates it against an Avro schema
    → registers the schema
    → sends Avro binary

kafka-console-consumer
    → cannot properly interpret Avro binary by itself

kafka-avro-console-consumer
    → reads the Schema ID
    → retrieves the Avro schema
    → decodes and prints JSON
```

The tools are mainly for **testing schemas, checking compatibility and debugging Avro topics**. Real Java or .NET applications use the corresponding Avro serializer and deserializer libraries.
