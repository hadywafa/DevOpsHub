# Java Kafka Consumer — Basic Consumer

This first example will:

1. Connect to Kafka.
2. Join a consumer group.
3. Subscribe to `orders`.
4. Continuously poll and print records.

We will handle **graceful shutdown separately** in the next topic.

---

## 1. Create the Java class

Create:

```text
src/main/java/com/hady/kafka/KafkaConsumerDemo.java
```

```java
package com.hady.kafka;

import org.apache.kafka.clients.consumer.ConsumerConfig;
import org.apache.kafka.clients.consumer.ConsumerRecord;
import org.apache.kafka.clients.consumer.ConsumerRecords;
import org.apache.kafka.clients.consumer.KafkaConsumer;
import org.apache.kafka.common.serialization.StringDeserializer;

import java.time.Duration;
import java.util.List;
import java.util.Properties;

public class KafkaConsumerDemo {

    private static final String BOOTSTRAP_SERVERS =
            "localhost:29092,localhost:39092,localhost:49092";

    private static final String TOPIC = "orders";
    private static final String GROUP_ID = "orders-java-consumer";

    public static void main(String[] args) {

        // 1. Consumer configuration
        Properties properties = new Properties();

        properties.setProperty(
                ConsumerConfig.BOOTSTRAP_SERVERS_CONFIG,
                BOOTSTRAP_SERVERS
        );

        properties.setProperty(
                ConsumerConfig.KEY_DESERIALIZER_CLASS_CONFIG,
                StringDeserializer.class.getName()
        );

        properties.setProperty(
                ConsumerConfig.VALUE_DESERIALIZER_CLASS_CONFIG,
                StringDeserializer.class.getName()
        );

        properties.setProperty(
                ConsumerConfig.GROUP_ID_CONFIG,
                GROUP_ID
        );

        properties.setProperty(
                ConsumerConfig.AUTO_OFFSET_RESET_CONFIG,
                "earliest"
        );

        // 2. Create consumer
        try (KafkaConsumer<String, String> consumer =
                     new KafkaConsumer<>(properties)) {

            // 3. Subscribe to the topic
            consumer.subscribe(List.of(TOPIC));

            System.out.println("Consumer started...");
            System.out.println("Topic: " + TOPIC);
            System.out.println("Group: " + GROUP_ID);

            // 4. Poll continuously
            while (true) {

                ConsumerRecords<String, String> records =
                        consumer.poll(Duration.ofMillis(1000));

                // 5. Process every received record
                for (ConsumerRecord<String, String> record : records) {

                    System.out.printf(
                            "key=%s, value=%s, partition=%d, offset=%d%n",
                            record.key(),
                            record.value(),
                            record.partition(),
                            record.offset()
                    );
                }
            }
        }
    }
}
```

# 3. Consumer configuration

## `bootstrap.servers`

```java
properties.setProperty(
        ConsumerConfig.BOOTSTRAP_SERVERS_CONFIG,
        "localhost:29092,localhost:39092,localhost:49092"
);
```

These are the Kafka broker addresses available from your host.

The consumer uses them only to make its initial connection and discover the cluster.

```text
Java consumer
      ↓ initial connection
Kafka broker
      ↓ metadata
Consumer discovers brokers and partitions
```

---

## Deserializers

```java
StringDeserializer.class.getName()
```

The producer used a serializer:

```text
Java String
    ↓
StringSerializer
    ↓
Kafka bytes
```

The consumer reverses the operation:

```text
Kafka bytes
    ↓
StringDeserializer
    ↓
Java String
```

Because our consumer is:

```java
KafkaConsumer<String, String>
```

the types are:

```text
Key   = String
Value = String
```

---

## `group.id`

```java
properties.setProperty(
        ConsumerConfig.GROUP_ID_CONFIG,
        "orders-java-consumer"
);
```

This consumer belongs to the group:

```text
orders-java-consumer
```

Kafka stores committed offsets separately for this group.

```text
orders-java-consumer
├── orders partition 0 offset
├── orders partition 1 offset
└── orders partition 2 offset
```

Consumers using the same group ID divide the topic partitions between themselves. The group ID is required when using group-managed subscription through `subscribe()`. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/consumer/KafkaConsumer.html 'KafkaConsumer (kafka 4.3.1 API)'))

---

## `auto.offset.reset`

```java
properties.setProperty(
        ConsumerConfig.AUTO_OFFSET_RESET_CONFIG,
        "earliest"
);
```

This means:

> When this group has no valid committed offset, start from the earliest retained record.

Important:

```text
New group with no committed offsets
→ earliest is used

Existing group with committed offsets
→ resume from committed offsets
```

Therefore, `earliest` does **not** force replay every time you restart the application. It applies only when no valid group offset exists. ([Conduktor](https://www.conduktor.io/kafka/complete-kafka-consumer-with-java 'Kafka Consumer in Java: A Complete Example | Conduktor'))

# 4. Create the consumer

```java
KafkaConsumer<String, String> consumer =
        new KafkaConsumer<>(properties);
```

This creates a Kafka client.

It does not immediately start receiving records.

```text
new KafkaConsumer(...)
→ Creates the client

consumer.subscribe(...)
→ Declares the topics

consumer.poll(...)
→ Joins the group and fetches records
```

A `KafkaConsumer` maintains network connections to the necessary brokers and participates in consumer-group coordination. It is also **not thread-safe**, so one consumer instance should normally be controlled by one thread. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/consumer/KafkaConsumer.html 'KafkaConsumer (kafka 4.3.1 API)'))

---

# 5. Subscribe to the topic

```java
consumer.subscribe(List.of(TOPIC));
```

Here:

```text
TOPIC = orders
```

You can subscribe to multiple topics:

```java
consumer.subscribe(
        List.of("orders", "payments", "notifications")
);
```

`subscribe()` enables Kafka’s consumer-group management. Kafka assigns partitions to consumers belonging to the group.

With one consumer:

```text
orders has 3 partitions

Consumer 1
├── Partition 0
├── Partition 1
└── Partition 2
```

With two consumers in the same group:

```text
Consumer 1
├── Partition 0
└── Partition 1

Consumer 2
└── Partition 2
```

We will demonstrate that separately in the consumer-group lesson.

# 6. The poll loop

```java
while (true) {

    ConsumerRecords<String, String> records =
            consumer.poll(Duration.ofMillis(1000));

    for (ConsumerRecord<String, String> record : records) {
        // Process record
    }
}
```

`poll()` is the central consumer operation.

It performs several responsibilities:

```text
poll()
├── Joins or maintains consumer-group membership
├── Receives partition assignments
├── Fetches available records
└── Sends consumer heartbeats when required
```

The duration:

```java
Duration.ofMillis(1000)
```

means that `poll()` can wait up to one second when no data is immediately available.

It does **not** mean that every call always waits exactly one second. If records are available, it can return earlier. ([Conduktor](https://www.conduktor.io/kafka/complete-kafka-consumer-with-java 'Kafka Consumer in Java: A Complete Example | Conduktor'))

---

# 7. `ConsumerRecords` versus `ConsumerRecord`

```java
ConsumerRecords<String, String> records =
        consumer.poll(Duration.ofMillis(1000));
```

`ConsumerRecords` is a batch containing zero or more records.

```text
ConsumerRecords
├── ConsumerRecord 1
├── ConsumerRecord 2
└── ConsumerRecord 3
```

Then:

```java
for (ConsumerRecord<String, String> record : records)
```

processes one individual record at a time.

---

# 8. Record information

```java
record.key()
record.value()
record.partition()
record.offset()
```

Example output:

```text
key=customer-1, value=order-1001, partition=2, offset=5
```

Meaning:

```text
Topic:     orders
Key:       customer-1
Value:     order-1001
Partition: 2
Offset:    5
```

An offset identifies a position inside one partition:

```text
orders partition 2

offset 3
offset 4
offset 5 ← this record
offset 6
```

If the consumer position is `6`, it has already returned records through offset `5`, and offset `6` is the next position it will read. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/consumer/KafkaConsumer.html 'KafkaConsumer (kafka 4.3.1 API)'))

# 11. Restart behaviour

Stop the Java application:

```text
Ctrl+C
```

Start it again using the same group:

```bash
mvn compile exec:java \
  -Dexec.mainClass=com.hady.kafka.KafkaConsumerDemo
```

It normally resumes from the group’s committed offsets instead of rereading all previous records.

To test a completely new group, change:

```java
private static final String GROUP_ID =
        "orders-java-consumer-v2";
```

Because this new group has no committed offsets and uses:

```java
auto.offset.reset=earliest
```

it reads all retained records from the beginning.

# What to memorise

```text
KafkaConsumer
→ Java client that reads Kafka records

StringDeserializer
→ Converts Kafka bytes into Java strings

group.id
→ Identifies one logical consuming application

subscribe()
→ Subscribe and let Kafka assign partitions

poll()
→ Join the group, maintain membership and retrieve records

ConsumerRecords
→ Batch returned by poll()

ConsumerRecord
→ One Kafka message

auto.offset.reset=earliest
→ Start from earliest only when no valid committed offset exists

Same group ID
→ Resume using that group's offsets

New group ID
→ Starts according to auto.offset.reset
```

The core consumer code is:

```java
consumer.subscribe(List.of("orders"));

while (true) {

    ConsumerRecords<String, String> records =
            consumer.poll(Duration.ofSeconds(1));

    for (ConsumerRecord<String, String> record : records) {
        System.out.println(record.value());
    }
}
```

This example stops abruptly with `Ctrl+C`. The next topic will add a shutdown hook, `consumer.wakeup()` and `consumer.close()` for a clean shutdown.
