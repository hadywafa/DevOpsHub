# Java Kafka Consumer — Inside a Consumer Group

A **consumer group** represents one logical application.

```text
Topic: orders — 3 partitions

Group: orders-java-group
├── Consumer 1 → some partitions
└── Consumer 2 → remaining partitions
```

Consumers with the same `group.id` divide the partitions. One partition can be assigned to only one active consumer within that group. ([Apache Kafka](https://kafka.apache.org/43/operations/basic-kafka-operations/?utm_source=chatgpt.com 'Basic Kafka Operations | Apache Kafka'))

---

## 1. Create the class

Create:

```text
src/main/java/com/hady/kafka/KafkaConsumerGroupDemo.java
```

```java
package com.hady.kafka;

import org.apache.kafka.clients.consumer.ConsumerConfig;
import org.apache.kafka.clients.consumer.ConsumerRecord;
import org.apache.kafka.clients.consumer.ConsumerRecords;
import org.apache.kafka.clients.consumer.KafkaConsumer;
import org.apache.kafka.common.errors.WakeupException;
import org.apache.kafka.common.serialization.StringDeserializer;

import java.time.Duration;
import java.util.List;
import java.util.Properties;

public class KafkaConsumerGroupDemo {

    private static final String BOOTSTRAP_SERVERS =
            "localhost:29092,localhost:39092,localhost:49092";

    private static final String TOPIC = "orders";

    // Same group ID for all instances.
    private static final String GROUP_ID = "orders-java-group";

    public static void main(String[] args) {

        // Give every running instance a readable name.
        String clientId = args.length > 0
                ? args[0]
                : "consumer-1";

        Properties properties = new Properties();

        properties.setProperty(
                ConsumerConfig.BOOTSTRAP_SERVERS_CONFIG,
                BOOTSTRAP_SERVERS
        );

        properties.setProperty(
                ConsumerConfig.KEY_DESERIALIZER_CLASS_CONFIG,
                StringDeserializer.class.getName()
        );

        properties.setProperty(
                ConsumerConfig.VALUE_DESERIALIZER_CLASS_CONFIG,
                StringDeserializer.class.getName()
        );

        properties.setProperty(
                ConsumerConfig.GROUP_ID_CONFIG,
                GROUP_ID
        );

        properties.setProperty(
                ConsumerConfig.CLIENT_ID_CONFIG,
                clientId
        );

        properties.setProperty(
                ConsumerConfig.AUTO_OFFSET_RESET_CONFIG,
                "earliest"
        );

        KafkaConsumer<String, String> consumer =
                new KafkaConsumer<>(properties);

        Runtime.getRuntime().addShutdownHook(
                new Thread(consumer::wakeup)
        );

        try {
            consumer.subscribe(List.of(TOPIC));

            System.out.printf(
                    "%s started in group %s%n",
                    clientId,
                    GROUP_ID
            );

            while (true) {

                ConsumerRecords<String, String> records =
                        consumer.poll(Duration.ofSeconds(1));

                for (ConsumerRecord<String, String> record : records) {

                    System.out.printf(
                            "[%s] partition=%d, offset=%d, key=%s, value=%s%n",
                            clientId,
                            record.partition(),
                            record.offset(),
                            record.key(),
                            record.value()
                    );
                }
            }

        } catch (WakeupException exception) {
            System.out.println(clientId + " shutting down");

        } finally {
            consumer.close();
        }
    }
}
```

## 2. `group.id` versus `client.id`

```java
ConsumerConfig.GROUP_ID_CONFIG
```

Defines the logical consumer group:

```text
orders-java-group
```

Consumers with the same group ID share partitions.

```java
ConsumerConfig.CLIENT_ID_CONFIG
```

Identifies one particular consumer instance:

```text
consumer-1
consumer-2
consumer-3
```

It is mainly useful for:

- Logs
- Metrics
- Troubleshooting
- Identifying group members

### Memorise

```text
group.id
→ Determines which consumers work together

client.id
→ Gives one consumer instance a readable name
```

Changing `client.id` does not create a separate consumer group.

## 3. Run the first consumer

Terminal 1:

```bash
mvn compile exec:java \
  -Dexec.mainClass=com.hady.kafka.KafkaConsumerGroupDemo \
  -Dexec.args="consumer-1"
```

With three topic partitions, the only consumer initially receives all three:

```text
consumer-1
├── orders-0
├── orders-1
└── orders-2
```

## 4. Run a second consumer

Terminal 2:

```bash
mvn compile exec:java \
  -Dexec.mainClass=com.hady.kafka.KafkaConsumerGroupDemo \
  -Dexec.args="consumer-2"
```

It uses the same:

```text
group.id = orders-java-group
```

Kafka performs a rebalance and redistributes the partitions:

```text
consumer-1
├── orders-0
└── orders-1

consumer-2
└── orders-2
```

The exact assignment may differ.

A rebalance occurs when group membership or subscribed partitions change, allowing Kafka to redistribute partition ownership. ([Apache Kafka](https://kafka.apache.org/43/operations/consumer-rebalance-protocol/?utm_source=chatgpt.com 'Consumer Rebalance Protocol | Apache Kafka'))

## 5. See the actual assignment

While both Java consumers are running:

```bash
docker compose exec kafka-1 \
  /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server kafka-1:19092 \
  --describe \
  --group orders-java-group \
  --members \
  --verbose
```

Example:

```text
CLIENT-ID   #PARTITIONS   ASSIGNMENT
consumer-1  2             orders(0,1)
consumer-2  1             orders(2)
```

This is the easiest command to verify which consumer owns each partition. ([Apache Kafka](https://kafka.apache.org/43/operations/basic-kafka-operations/?utm_source=chatgpt.com 'Basic Kafka Operations | Apache Kafka'))

## 6. Produce messages

```bash
docker compose exec kafka-1 \
  /opt/kafka/bin/kafka-console-producer.sh \
  --bootstrap-server kafka-1:19092 \
  --topic orders
```

Enter:

```text
order-1
order-2
order-3
order-4
order-5
```

You will see the messages divided between the two Java terminals according to partition ownership.

A message is not delivered to both consumers because they belong to the same group.

## 8. Start a fourth consumer

```bash
mvn compile exec:java \
  -Dexec.mainClass=com.hady.kafka.KafkaConsumerGroupDemo \
  -Dexec.args="consumer-4"
```

There are only three partitions:

```text
consumer-1 → one partition
consumer-2 → one partition
consumer-3 → one partition
consumer-4 → idle
```

### Rule

```text
Useful consumers in one group
≤
Number of topic partitions
```

An idle consumer remains a group member but receives no partition assignment.

## 9. Different consumer group

Change:

```java
private static final String GROUP_ID =
        "orders-analytics-group";
```

This creates another logical application:

```text
orders-java-group
→ Reads every order once for order processing

orders-analytics-group
→ Independently reads every order for analytics
```

Kafka stores separate committed offsets for each group.

```text
Same group ID
→ Consumers share the records

Different group IDs
→ Each group reads all records independently
```

## What to memorise

```text
subscribe()
→ Kafka manages partition assignment

Same group.id
→ Consumers divide partitions

Different group.id
→ Groups consume independently

One partition
→ Only one active consumer in the group

More consumers than partitions
→ Extra consumers are idle

Consumer joins or leaves
→ Kafka rebalances the group

group.id
→ Logical application identity

client.id
→ Individual consumer identity
```
