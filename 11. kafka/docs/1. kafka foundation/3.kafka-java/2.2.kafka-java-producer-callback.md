
# Java Kafka Producer — Callback

In the previous example:

```java
producer.send(record);
```

The send is **asynchronous**. Your application does not immediately know:

- Whether the message succeeded

- Which partition received it

- Which offset Kafka assigned

- Whether an error occurred

A **callback** runs after Kafka finishes processing the send request. `send(record, callback)` still returns immediately; Kafka later invokes the callback with the result. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/producer/KafkaProducer.html "KafkaProducer (kafka 4.3.1 API)"))

---

## 1. Create the class

Create:

```text
src/main/java/com/hady/kafka/KafkaProducerCallbackDemo.java
```

```java
package com.hady.kafka;

import org.apache.kafka.clients.producer.KafkaProducer;
import org.apache.kafka.clients.producer.ProducerConfig;
import org.apache.kafka.clients.producer.ProducerRecord;
import org.apache.kafka.common.serialization.StringSerializer;

import java.util.Properties;

public class KafkaProducerCallbackDemo {

    public static void main(String[] args) {

        Properties properties = new Properties();

        properties.setProperty(
                ProducerConfig.BOOTSTRAP_SERVERS_CONFIG,
                "localhost:29092,localhost:39092,localhost:49092"
        );

        properties.setProperty(
                ProducerConfig.KEY_SERIALIZER_CLASS_CONFIG,
                StringSerializer.class.getName()
        );

        properties.setProperty(
                ProducerConfig.VALUE_SERIALIZER_CLASS_CONFIG,
                StringSerializer.class.getName()
        );

        try (KafkaProducer<String, String> producer =
                     new KafkaProducer<>(properties)) {

            ProducerRecord<String, String> record =
                    new ProducerRecord<>(
                            "orders",
                            "Hello Kafka with callback"
                    );

            producer.send(record, (metadata, exception) -> {

                if (exception != null) {
                    System.err.println(
                            "Message failed: " + exception.getMessage()
                    );
                    return;
                }

                System.out.println("Message sent successfully");
                System.out.println("Topic: " + metadata.topic());
                System.out.println("Partition: " + metadata.partition());
                System.out.println("Offset: " + metadata.offset());
                System.out.println("Timestamp: " + metadata.timestamp());
            });

            producer.flush();
        }
    }
}
```

## 2. The important change

Previously:

```java
producer.send(record);
```

Now:

```java
producer.send(record, (metadata, exception) -> {
    // Handle the result
});
```

The callback receives two values:

```text
metadata
→ Information about a successful send

exception
→ Information about a failed send
```

On success, `exception` is `null`. On failure, `exception` contains the error, while the metadata fields are unavailable or represented with special `-1` values. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/producer/Callback.html "Callback (kafka 4.3.1 API)"))

---

## 3. Success handling

```java
if (exception == null) {
    System.out.println("Partition: " + metadata.partition());
    System.out.println("Offset: " + metadata.offset());
}
```

`RecordMetadata` tells you where Kafka stored the record:

```text
Topic:     orders
Partition: 1
Offset:    5
Timestamp: ...
```

Kafka assigns offsets separately inside each partition:

```text
orders partition 1:

offset 0
offset 1
offset 2
...
offset 5  ← your record
```

The metadata returned after acknowledgement includes the selected partition, assigned offset and record timestamp. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/producer/KafkaProducer.html "KafkaProducer (kafka 4.3.1 API)"))

---

## 4. Failure handling

```java
if (exception != null) {
    System.err.println(
            "Message failed: " + exception.getMessage()
    );
    return;
}
```

Possible reasons include:

```text
Kafka cluster unavailable
Topic does not exist
Authentication failure
Authorisation failure
Serialization failure
Request timeout
```

Always check the exception **before** reading metadata.

Recommended pattern:

```java
producer.send(record, (metadata, exception) -> {

    if (exception != null) {
        System.err.println("Send failed");
        exception.printStackTrace();
        return;
    }

    System.out.printf(
            "Sent to topic=%s partition=%d offset=%d%n",
            metadata.topic(),
            metadata.partition(),
            metadata.offset()
    );
});
```

## 6. Why `flush()` is still present

```java
producer.flush();
```

The callback runs later because sending is asynchronous.

Without `flush()` or `close()`, a short application might terminate before the send completes.

```text
producer.send(...)
→ Queue the message

producer.flush()
→ Wait for pending sends and callbacks
```

After `flush()` returns, callbacks for records sent before the flush have completed. The producer’s `close()` also waits for previously sent requests, and the try-with-resources block calls it automatically. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/producer/KafkaProducer.html "KafkaProducer (kafka 4.3.1 API)"))

Do not call `flush()` inside the callback; Kafka documents that this can deadlock and throws an exception. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/producer/KafkaProducer.html "KafkaProducer (kafka 4.3.1 API)"))

## 7. Send multiple messages with callbacks

```java
for (int i = 1; i <= 5; i++) {

    String value = "Order number " + i;

    ProducerRecord<String, String> record =
            new ProducerRecord<>("orders", value);

    producer.send(record, (metadata, exception) -> {

        if (exception != null) {
            System.err.println(
                    "Failed to send: " + value
            );
            return;
        }

        System.out.printf(
                "Value=%s, partition=%d, offset=%d%n",
                value,
                metadata.partition(),
                metadata.offset()
        );
    });
}

producer.flush();
```

Possible output:

```text
Value=Order number 1, partition=0, offset=5
Value=Order number 2, partition=2, offset=3
Value=Order number 3, partition=1, offset=8
Value=Order number 4, partition=0, offset=6
Value=Order number 5, partition=2, offset=4
```

Callbacks generally execute on the producer’s background I/O thread, so callback code should remain fast. Avoid slow database calls or heavy processing directly inside it. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/producer/Callback.html "Callback (kafka 4.3.1 API)"))

## What to memorise

```text
producer.send(record)
→ Send asynchronously without result handling

producer.send(record, callback)
→ Send asynchronously and handle success or failure

exception != null
→ Send failed

exception == null
→ Send succeeded

RecordMetadata
→ Topic, partition, offset and timestamp

flush()
→ Wait for pending sends and callbacks
```

The essential callback pattern is:

```java
producer.send(record, (metadata, exception) -> {

    if (exception != null) {
        exception.printStackTrace();
        return;
    }

    System.out.println(
            "Partition=" + metadata.partition()
            + ", Offset=" + metadata.offset()
    );
});
```
