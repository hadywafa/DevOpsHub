# Java Kafka Producer — Basic Producer

We will create a producer that sends one simple message:

```text
Topic: orders
Key:   null
Value: Hello Kafka from Java
```

No callback and no key yet.

---

## 1. Create the Java class

Create:

```text
src/main/java/com/hady/kafka/KafkaProducerDemo.java
```

```java
package com.hady.kafka;

import org.apache.kafka.clients.producer.KafkaProducer;
import org.apache.kafka.clients.producer.ProducerConfig;
import org.apache.kafka.clients.producer.ProducerRecord;
import org.apache.kafka.common.serialization.StringSerializer;

import java.util.Properties;

public class KafkaProducerDemo {

    public static void main(String[] args) {

        // 1. Producer configuration
        Properties properties = new Properties();

        properties.setProperty(
                ProducerConfig.BOOTSTRAP_SERVERS_CONFIG,
                "localhost:29092,localhost:39092,localhost:49092"
        );

        properties.setProperty(
                ProducerConfig.KEY_SERIALIZER_CLASS_CONFIG,
                StringSerializer.class.getName()
        );

        properties.setProperty(
                ProducerConfig.VALUE_SERIALIZER_CLASS_CONFIG,
                StringSerializer.class.getName()
        );

        // 2. Create the Kafka producer
        try (KafkaProducer<String, String> producer =
                     new KafkaProducer<>(properties)) {

            // 3. Create the record
            ProducerRecord<String, String> record =
                    new ProducerRecord<>(
                            "orders",
                            "Hello Kafka from Java"
                    );

            // 4. Send the record
            producer.send(record);

            // 5. Wait until buffered records are sent
            producer.flush();

            System.out.println("Message sent successfully");
        }
    }
}
```

---

# 2. Understand the code

## Producer properties

```java
Properties properties = new Properties();
```

This holds the Kafka producer configuration.

Think of it like:

```text
Producer configuration
├── Kafka addresses
├── Key serializer
└── Value serializer
```

---

## `bootstrap.servers`

```java
properties.setProperty(
    ProducerConfig.BOOTSTRAP_SERVERS_CONFIG,
    "localhost:29092,localhost:39092,localhost:49092"
);
```

These are the Kafka addresses exposed from Docker to your host.

```text
Java application
      ↓
localhost:29092
localhost:39092
localhost:49092
      ↓
Kafka cluster
```

The producer initially contacts one available bootstrap broker, receives cluster metadata, and then connects directly to the correct partition leader. The list does not need every broker, but using multiple addresses makes the initial connection more resilient.

---

## Serializers

```java
properties.setProperty(
    ProducerConfig.KEY_SERIALIZER_CLASS_CONFIG,
    StringSerializer.class.getName()
);
```

```java
properties.setProperty(
    ProducerConfig.VALUE_SERIALIZER_CLASS_CONFIG,
    StringSerializer.class.getName()
);
```

Kafka stores bytes, not Java objects.

The serializer converts:

```text
Java String
    ↓ StringSerializer
byte[]
    ↓
Kafka
```

Our types are:

```java
KafkaProducer<String, String>
```

Meaning:

```text
Key type   = String
Value type = String
```

Therefore, we use `StringSerializer` for both.

The producer requires serializer configuration for keys and values.

Even though this example does not provide a key, keeping the key serializer configured allows the producer to handle string keys later.

---

## Create the producer

```java
KafkaProducer<String, String> producer =
        new KafkaProducer<>(properties);
```

This creates the Kafka client.

It does not immediately create a new Kafka broker or topic.

```text
KafkaProducer object
→ Client used to send records to Kafka
```

We use `try (...)` so Java automatically closes the producer. Kafka recommends always closing a producer to release its network connections, buffers, and other resources. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/producer/KafkaProducer.html?utm_source=chatgpt.com 'KafkaProducer (kafka 4.3.1 API)'))

---

## Create the record

```java
ProducerRecord<String, String> record =
        new ProducerRecord<>(
                "orders",
                "Hello Kafka from Java"
        );
```

The constructor here is:

```text
ProducerRecord(topic, value)
```

So the record is:

```text
Topic: orders
Key:   null
Value: Hello Kafka from Java
```

A `ProducerRecord` represents a key/value record sent to a Kafka topic; its key and explicit partition are optional. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/producer/ProducerRecord.html?utm_source=chatgpt.com 'ProducerRecord (kafka 4.3.1 API)'))

Because we did not specify a partition, the producer chooses one.

---

## Send

```java
producer.send(record);
```

This sends the record asynchronously.

Conceptually:

```text
Application thread
      ↓
Producer buffer
      ↓
Kafka producer network thread
      ↓
Partition leader
```

The method does not normally wait for the entire network operation to finish before returning.

We will handle the result using a callback in the next lesson.

---

## Flush

```java
producer.flush();
```

This waits until the records currently buffered by the producer have completed sending.

Without it, the application could reach the end too quickly during a small demo.

```text
send()
→ Add the record to the producer

flush()
→ Wait for pending records
```

In a long-running real application, you normally do not call `flush()` after every message because that reduces batching and throughput.

# 3. Create the topic

Run from your Kafka Compose directory:

```bash
docker compose exec kafka-1 \
  /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server kafka-1:19092 \
  --create \
  --if-not-exists \
  --topic orders \
  --partitions 3 \
  --replication-factor 3
```

---

# 4. Start a consumer to observe the message

In another terminal:

```bash
docker compose exec kafka-1 \
  /opt/kafka/bin/kafka-console-consumer.sh \
  --bootstrap-server kafka-1:19092 \
  --topic orders \
  --from-beginning
```

Leave it running.

---

# 5. Run the Maven producer

From your Maven project directory:

```bash
mvn clean compile exec:java \
  -Dexec.mainClass=com.hady.kafka.KafkaProducerDemo
```

Expected Java output:

```text
Message sent successfully
```

Expected consumer output:

```text
Hello Kafka from Java
```

# 6. Send multiple messages

Change the producer body to:

```java
try (KafkaProducer<String, String> producer =
             new KafkaProducer<>(properties)) {

    for (int i = 1; i <= 5; i++) {

        ProducerRecord<String, String> record =
                new ProducerRecord<>(
                        "orders",
                        "Order number " + i
                );

        producer.send(record);
    }

    producer.flush();

    System.out.println("Five messages sent successfully");
}
```

Consumer output:

```text
Order number 1
Order number 2
Order number 3
Order number 4
Order number 5
```

The records may be spread across different partitions because they do not have keys. Kafka guarantees ordering inside one partition, not global ordering across the entire topic.

# Flow to memorise

```text
1. Configure Properties
        ↓
2. Create KafkaProducer
        ↓
3. Create ProducerRecord
        ↓
4. producer.send(record)
        ↓
5. producer.flush()
        ↓
6. producer.close()
```

The important objects are:

```text
Properties
→ Producer configuration

KafkaProducer
→ Kafka client

ProducerRecord
→ One message to send

StringSerializer
→ Converts Java String to bytes
```

The smallest producer logic is:

```java
ProducerRecord<String, String> record =
        new ProducerRecord<>("orders", "Hello Kafka");

producer.send(record);
producer.flush();
```
