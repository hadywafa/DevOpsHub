# Java Kafka Consumer — Graceful Shutdown

Our previous consumer used:

```java
while (true) {
    consumer.poll(...);
}
```

Pressing `Ctrl+C` stops the JVM. We should first:

```text
Interrupt poll()
→ Exit the loop
→ Close the consumer
→ Release connections and leave the group cleanly
```

Kafka provides `consumer.wakeup()` specifically for this purpose. It is the one consumer method that can safely be called from another thread. It interrupts `poll()` by throwing `WakeupException`. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/consumer/KafkaConsumer.html 'KafkaConsumer (kafka 4.3.1 API)'))

---

## 1. Create the class

Create:

```text
src/main/java/com/hady/kafka/KafkaConsumerGracefulShutdownDemo.java
```

```java
package com.hady.kafka;

import org.apache.kafka.clients.consumer.ConsumerConfig;
import org.apache.kafka.clients.consumer.ConsumerRecord;
import org.apache.kafka.clients.consumer.ConsumerRecords;
import org.apache.kafka.clients.consumer.KafkaConsumer;
import org.apache.kafka.common.errors.WakeupException;
import org.apache.kafka.common.serialization.StringDeserializer;

import java.time.Duration;
import java.util.List;
import java.util.Properties;
import java.util.concurrent.atomic.AtomicBoolean;

public class KafkaConsumerGracefulShutdownDemo {

    private static final String BOOTSTRAP_SERVERS =
            "localhost:29092,localhost:39092,localhost:49092";

    private static final String TOPIC = "orders";
    private static final String GROUP_ID = "orders-java-consumer";

    public static void main(String[] args) {

        Properties properties = new Properties();

        properties.setProperty(
                ConsumerConfig.BOOTSTRAP_SERVERS_CONFIG,
                BOOTSTRAP_SERVERS
        );

        properties.setProperty(
                ConsumerConfig.KEY_DESERIALIZER_CLASS_CONFIG,
                StringDeserializer.class.getName()
        );

        properties.setProperty(
                ConsumerConfig.VALUE_DESERIALIZER_CLASS_CONFIG,
                StringDeserializer.class.getName()
        );

        properties.setProperty(
                ConsumerConfig.GROUP_ID_CONFIG,
                GROUP_ID
        );

        properties.setProperty(
                ConsumerConfig.AUTO_OFFSET_RESET_CONFIG,
                "earliest"
        );

        KafkaConsumer<String, String> consumer =
                new KafkaConsumer<>(properties);

        AtomicBoolean shuttingDown = new AtomicBoolean(false);

        /*
         * This thread runs when:
         * - Ctrl+C is pressed
         * - SIGTERM is sent
         * - The JVM begins shutting down
         */
        Runtime.getRuntime().addShutdownHook(
                new Thread(() -> {
                    System.out.println("Shutdown requested...");

                    shuttingDown.set(true);

                    // Interrupt consumer.poll()
                    consumer.wakeup();
                })
        );

        try {
            consumer.subscribe(List.of(TOPIC));

            System.out.println("Consumer started");
            System.out.println("Press Ctrl+C to stop");

            while (true) {

                ConsumerRecords<String, String> records =
                        consumer.poll(Duration.ofSeconds(1));

                for (ConsumerRecord<String, String> record : records) {

                    System.out.printf(
                            "key=%s, value=%s, partition=%d, offset=%d%n",
                            record.key(),
                            record.value(),
                            record.partition(),
                            record.offset()
                    );
                }
            }

        } catch (WakeupException exception) {

            // WakeupException is expected during shutdown.
            if (!shuttingDown.get()) {
                throw exception;
            }

            System.out.println("Consumer poll stopped");

        } finally {

            System.out.println("Closing consumer...");

            consumer.close();

            System.out.println("Consumer closed successfully");
        }
    }
}
```

## 2. What happens when you press `Ctrl+C`?

```text
Ctrl+C
   ↓
JVM runs shutdown hook
   ↓
shuttingDown = true
   ↓
consumer.wakeup()
   ↓
poll() throws WakeupException
   ↓
catch WakeupException
   ↓
finally
   ↓
consumer.close()
```

---

## 3. The shutdown hook

```java
Runtime.getRuntime().addShutdownHook(
        new Thread(() -> {
            shuttingDown.set(true);
            consumer.wakeup();
        })
);
```

A shutdown hook is a thread that Java runs while the JVM is shutting down.

Typical triggers include:

```text
Ctrl+C
kill -TERM <pid>
Kubernetes Pod termination
Docker container stop
```

The hook should not call most consumer operations because `KafkaConsumer` is not thread-safe. `wakeup()` is the important exception: Kafka explicitly allows it to be called from another thread. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/consumer/KafkaConsumer.html 'KafkaConsumer (kafka 4.3.1 API)'))

---

## 4. Why use `consumer.wakeup()`?

The main thread may currently be blocked here:

```java
consumer.poll(Duration.ofSeconds(1));
```

The shutdown hook runs on a different thread.

Calling:

```java
consumer.wakeup();
```

causes the active or next blocking consumer operation to throw:

```java
WakeupException
```

This allows the main consumer thread to escape the poll loop safely. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/consumer/KafkaConsumer.html 'KafkaConsumer (kafka 4.3.1 API)'))

Do not use:

```java
Thread.currentThread().interrupt();
```

as the normal Kafka shutdown mechanism. Kafka recommends `wakeup()` because thread interruption can interfere with clean consumer shutdown. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/consumer/KafkaConsumer.html 'KafkaConsumer (kafka 4.3.1 API)'))

---

## 5. Why check `shuttingDown`?

```java
catch (WakeupException exception) {

    if (!shuttingDown.get()) {
        throw exception;
    }
}
```

A `WakeupException` is expected when we intentionally stop the application.

```text
shuttingDown = true
→ Expected exception
→ Continue to finally

shuttingDown = false
→ Unexpected exception
→ Rethrow it
```

This prevents us from hiding an unexpected problem.

---

## 6. Why use `finally`?

```java
finally {
    consumer.close();
}
```

The `finally` block runs whether:

- Shutdown was requested.
- Processing threw an exception.
- `poll()` threw `WakeupException`.

Closing the consumer releases its broker connections and performs consumer cleanup. Kafka warns that failing to close a consumer leaks its TCP connections. The no-argument `close()` waits up to its default timeout for cleanup and can commit current offsets when auto-commit is enabled. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/consumer/KafkaConsumer.html 'KafkaConsumer (kafka 4.3.1 API)'))

## Abrupt versus graceful shutdown

### Abrupt shutdown

```text
Process disappears
→ Broker eventually detects failure
→ Group waits for failure timeout
→ Partitions are reassigned
```

### Graceful shutdown

```text
consumer.wakeup()
→ poll loop stops
→ consumer.close()
→ Consumer cleanup occurs
→ Group can rebalance cleanly
```

## What to memorise

```text
Shutdown hook
→ Detect JVM shutdown or Ctrl+C

consumer.wakeup()
→ Safely interrupt poll() from another thread

WakeupException
→ Expected when wakeup() interrupts poll()

finally
→ Always close the consumer

consumer.close()
→ Clean up resources and consumer-group membership
```

The essential pattern is:

```java
Runtime.getRuntime().addShutdownHook(
        new Thread(consumer::wakeup)
);

try {

    while (true) {
        consumer.poll(Duration.ofSeconds(1));
    }

} catch (WakeupException exception) {

    // Expected during shutdown

} finally {

    consumer.close();
}
```
