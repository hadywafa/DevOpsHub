# Java Kafka Producer — With Keys

![[Pasted image 20260726203519.png]]

A Kafka record can contain:

```text
Key   = customer-1
Value = order-1001
```

The key controls **which partition receives the record**.

```text
Same key
   ↓
Same partition
   ↓
Ordering preserved for that key
```

---

## 1. Create the Java class

Create:

```text
src/main/java/com/hady/kafka/KafkaProducerWithKeysDemo.java
```

```java
package com.hady.kafka;

import org.apache.kafka.clients.producer.KafkaProducer;
import org.apache.kafka.clients.producer.ProducerConfig;
import org.apache.kafka.clients.producer.ProducerRecord;
import org.apache.kafka.common.serialization.StringSerializer;

import java.util.Properties;

public class KafkaProducerWithKeysDemo {

    public static void main(String[] args) {

        Properties properties = new Properties();

        properties.setProperty(
                ProducerConfig.BOOTSTRAP_SERVERS_CONFIG,
                "localhost:29092,localhost:39092,localhost:49092"
        );

        properties.setProperty(
                ProducerConfig.KEY_SERIALIZER_CLASS_CONFIG,
                StringSerializer.class.getName()
        );

        properties.setProperty(
                ProducerConfig.VALUE_SERIALIZER_CLASS_CONFIG,
                StringSerializer.class.getName()
        );

        try (KafkaProducer<String, String> producer =
                     new KafkaProducer<>(properties)) {

            send(producer, "customer-1", "order-1001");
            send(producer, "customer-2", "order-1002");
            send(producer, "customer-1", "order-1003");
            send(producer, "customer-3", "order-1004");
            send(producer, "customer-2", "order-1005");

            producer.flush();
        }
    }

    private static void send(
            KafkaProducer<String, String> producer,
            String key,
            String value
    ) {

        ProducerRecord<String, String> record =
                new ProducerRecord<>(
                        "orders",
                        key,
                        value
                );

        producer.send(record, (metadata, exception) -> {

            if (exception != null) {
                System.err.printf(
                        "Failed: key=%s, value=%s%n",
                        key,
                        value
                );

                exception.printStackTrace();
                return;
            }

            System.out.printf(
                    "key=%s, value=%s → partition=%d, offset=%d%n",
                    key,
                    value,
                    metadata.partition(),
                    metadata.offset()
            );
        });
    }
}
```

---

## 2. Important `ProducerRecord` constructor

```java
new ProducerRecord<>(
        "orders",
        key,
        value
);
```

This constructor means:

```text
ProducerRecord(topic, key, value)
```

Example:

```java
new ProducerRecord<>(
        "orders",
        "customer-1",
        "order-1001"
);
```

Creates:

```text
Topic: orders
Key:   customer-1
Value: order-1001
```

Because no partition was explicitly specified, Kafka chooses one using a hash of the serialized key. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/producer/ProducerRecord.html?utm_source=chatgpt.com 'ProducerRecord (kafka 4.3.1 API)'))

## 5. Why keys are important

Imagine events about one order:

```text
order-1001 → CREATED
order-1001 → PAID
order-1001 → SHIPPED
```

Use the order ID as the key:

```java
send(producer, "order-1001", "CREATED");
send(producer, "order-1001", "PAID");
send(producer, "order-1001", "SHIPPED");
```

Kafka sends them to the same partition:

```text
Partition 1

Offset 10 → CREATED
Offset 11 → PAID
Offset 12 → SHIPPED
```

Therefore, the order is preserved for `order-1001`.

## 6. Key serializers

Our producer declares:

```java
KafkaProducer<String, String>
```

So both key and value are strings:

```text
Key type   = String
Value type = String
```

Therefore:

```java
KEY_SERIALIZER_CLASS_CONFIG   = StringSerializer
VALUE_SERIALIZER_CLASS_CONFIG = StringSerializer
```

Kafka hashes the **serialized key bytes**, not the original Java object directly.

---

## 7. Important rules

### Same key normally means same partition

```text
customer-1 → partition 2
customer-1 → partition 2
customer-1 → partition 2
```

This assumes the topic’s partition count does not change.

---

### Different keys can share a partition

Three keys do not necessarily require three partitions:

```text
customer-1 → partition 0
customer-2 → partition 0
customer-3 → partition 2
```

Kafka hashes keys into the available partitions, so collisions are normal.

---

### Ordering is per partition

Kafka does not guarantee total ordering across the entire topic:

```text
Partition 0 → independent order
Partition 1 → independent order
Partition 2 → independent order
```

It guarantees ordering within each partition.

---

### Changing partition count can remap keys

Suppose:

```text
customer-1 → partition 1 of 3
```

After increasing the topic to six partitions, the same key may map differently:

```text
customer-1 → partition 4 of 6
```

Therefore, be careful when increasing partitions for topics that depend on key ordering.

---

### Explicit partition overrides key-based selection

This constructor specifies partition `1` manually:

```java
ProducerRecord<String, String> record =
        new ProducerRecord<>(
                "orders",
                1,
                "customer-1",
                "order-1001"
        );
```

Meaning:

```text
Topic:     orders
Partition: 1
Key:       customer-1
Value:     order-1001
```

Kafka uses partition `1`; it does not hash the key to select another partition. ([Apache Kafka](https://kafka.apache.org/43/javadoc/org/apache/kafka/clients/producer/ProducerRecord.html?utm_source=chatgpt.com 'ProducerRecord (kafka 4.3.1 API)'))

Usually, prefer:

```java
new ProducerRecord<>("orders", key, value);
```

and allow Kafka to select the partition from the key.

---

## What to memorise

```text
ProducerRecord(topic, key, value)
→ Send a keyed record

Same key
→ Same partition, while partition count stays unchanged

Same partition
→ Ordered records

Different keys
→ May use different partitions or share one

Explicit partition
→ Overrides key-based selection

Best key
→ Business identifier whose events need ordering
```

Typical keys:

```text
orderId
customerId
accountId
deviceId
transactionId
```
