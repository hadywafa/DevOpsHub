# Kafka CLI — Practical Cheat Sheet

This covers what we learned:

```text
Topics → Producer → Consumer → Consumer Groups → Reset Offsets
```

Run everything from the `kafka-kraft-lab` directory.

---

## 0. Create reusable terminal shortcuts

Copy this once into your terminal:

```bash
export BS="kafka-1:19092"
export TOPIC="orders"
export GROUP="orders-service"

kafka() {
  local tool="$1"
  shift
  docker compose exec kafka-1 "/opt/kafka/bin/$tool" "$@"
}

kafka_pipe() {
  local tool="$1"
  shift
  docker compose exec -T kafka-1 "/opt/kafka/bin/$tool" "$@"
}
```

Now instead of writing:

```bash
docker compose exec kafka-1 \
  /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server kafka-1:19092 \
  --list
```

you can write:

```bash
kafka kafka-topics.sh --bootstrap-server "$BS" --list
```

These variables and functions exist only in the current terminal session.

# 1. Topics

## Create a topic

```bash
kafka kafka-topics.sh \
  --bootstrap-server "$BS" \
  --create \
  --if-not-exists \
  --topic "$TOPIC" \
  --partitions 3 \
  --replication-factor 3
```

Important:

```text
Topic: orders
Partitions: orders-0, orders-1, orders-2
```

Partitions provide parallelism and ordering boundaries.

---

## List topics

```bash
kafka kafka-topics.sh \
  --bootstrap-server "$BS" \
  --list
```

---

## Describe a topic

```bash
kafka kafka-topics.sh \
  --bootstrap-server "$BS" \
  --describe \
  --topic "$TOPIC"
```

Focus on:

```text
Partition
Leader
Replicas
ISR
```

---

## Increase partitions

Change the total from `3` to `6`:

```bash
kafka kafka-topics.sh \
  --bootstrap-server "$BS" \
  --alter \
  --topic "$TOPIC" \
  --partitions 6
```

Important rules:

```text
--partitions 6 means total partitions = 6
Partitions can be increased
Partitions cannot be decreased
```

Increasing partitions may change which partition receives a particular key, so plan the original partition count carefully.

---

## Show topic configuration

```bash
kafka kafka-configs.sh \
  --bootstrap-server "$BS" \
  --entity-type topics \
  --entity-name "$TOPIC" \
  --describe
```

---

## Change retention to one day

```bash
kafka kafka-configs.sh \
  --bootstrap-server "$BS" \
  --entity-type topics \
  --entity-name "$TOPIC" \
  --alter \
  --add-config retention.ms=86400000
```

Remove the override:

```bash
kafka kafka-configs.sh \
  --bootstrap-server "$BS" \
  --entity-type topics \
  --entity-name "$TOPIC" \
  --alter \
  --delete-config retention.ms
```

Removing the override means the topic inherits the broker default again.

---

## Delete a topic

```bash
kafka kafka-topics.sh \
  --bootstrap-server "$BS" \
  --delete \
  --topic "$TOPIC"
```

This deletes the topic and its records.

# 2. Producer

## Produce simple messages interactively

```bash
kafka kafka-console-producer.sh \
  --bootstrap-server "$BS" \
  --topic "$TOPIC"
```

Enter:

```text
order-1
order-2
order-3
```

Rule:

```text
Each input line = one Kafka record
```

Exit with:

```text
Ctrl+D
```

---

## Produce messages from the command line

```bash
printf 'order-1\norder-2\norder-3\n' |
kafka_pipe kafka-console-producer.sh \
  --bootstrap-server "$BS" \
  --topic "$TOPIC"
```

`kafka_pipe` uses Docker’s `-T` option because the input comes from a pipe.

---

## Produce keyed messages

```bash
kafka kafka-console-producer.sh \
  --bootstrap-server "$BS" \
  --topic "$TOPIC" \
  --reader-property parse.key=true \
  --reader-property 'key.separator=|'
```

Enter:

```text
customer-1|order-1
customer-2|order-2
customer-1|order-3
```

Kafka records:

```text
Key: customer-1    Value: order-1
Key: customer-2    Value: order-2
Key: customer-1    Value: order-3
```

Important rule:

```text
Same key
→ Normally goes to the same partition
→ Maintains ordering for that key
```

Kafka guarantees ordering **inside a partition**, not across the entire topic.

---

## Produce reusable keyed test data

```bash
printf '%s\n' \
  'customer-1|order-1' \
  'customer-2|order-2' \
  'customer-3|order-3' \
  'customer-1|order-4' \
  'customer-2|order-5' \
  'customer-3|order-6' |
kafka_pipe kafka-console-producer.sh \
  --bootstrap-server "$BS" \
  --topic "$TOPIC" \
  --reader-property parse.key=true \
  --reader-property 'key.separator=|'
```

Kafka 4.3 uses `--reader-property` for console-producer input parsing. Producer defaults include `acks=all` and idempotence enabled when there are no conflicting settings. ([Apache Kafka](https://kafka.apache.org/43/getting-started/upgrade/?utm_source=chatgpt.com 'Upgrading | Apache Kafka'))

# 3. Consumer

## Consume only new messages

Start this first:

```bash
kafka kafka-console-consumer.sh \
  --bootstrap-server "$BS" \
  --topic "$TOPIC"
```

Then produce messages in another terminal.

Without `--from-beginning`, a new consumer starts at the latest position by default.

---

## Consume all retained messages

```bash
kafka kafka-console-consumer.sh \
  --bootstrap-server "$BS" \
  --topic "$TOPIC" \
  --from-beginning
```

Without a named group, this is useful for inspecting the topic.

---

## Show key, partition and offset

```bash
kafka kafka-console-consumer.sh \
  --bootstrap-server "$BS" \
  --topic "$TOPIC" \
  --from-beginning \
  --formatter-property print.partition=true \
  --formatter-property print.offset=true \
  --formatter-property print.key=true \
  --formatter-property 'key.separator= | '
```

Example:

```text
Partition:0 | Offset:0 | customer-1 | order-1
Partition:0 | Offset:1 | customer-1 | order-4
Partition:2 | Offset:0 | customer-2 | order-2
```

This demonstrates:

```text
Same key → same partition
Offset increases separately inside each partition
```

Kafka 4.3 uses `--formatter-property` for console-consumer output formatting. ([Apache Kafka](https://kafka.apache.org/43/getting-started/upgrade/?utm_source=chatgpt.com 'Upgrading | Apache Kafka'))

---

## Read one partition from one offset

```bash
kafka kafka-console-consumer.sh \
  --bootstrap-server "$BS" \
  --topic "$TOPIC" \
  --partition 0 \
  --offset 1 \
  --formatter-property print.offset=true \
  --formatter-property print.key=true
```

This reads:

```text
Partition 0, starting from offset 1
```

Useful for investigating a specific record.

Do not combine manual `--partition` assignment with `--group`.

# 4. Consumer Groups

A named group is created when a consumer starts with `--group`.

```bash
kafka kafka-console-consumer.sh \
  --bootstrap-server "$BS" \
  --topic "$TOPIC" \
  --group "$GROUP" \
  --from-beginning
```

Stop it after consuming using:

```text
Ctrl+C
```

Important behaviour:

```text
First run:
No committed offset → --from-beginning starts at earliest

Later runs:
Committed offset exists → consumer resumes from that offset
```

`--from-beginning` does not override an existing committed offset. `auto.offset.reset` is used only when there is no valid committed offset; its default is `latest`.

---

## Start the same group again

```bash
kafka kafka-console-consumer.sh \
  --bootstrap-server "$BS" \
  --topic "$TOPIC" \
  --group "$GROUP"
```

It resumes instead of replaying everything.

---

## List consumer groups

```bash
kafka kafka-consumer-groups.sh \
  --bootstrap-server "$BS" \
  --list
```

---

## Show offsets and lag

```bash
kafka kafka-consumer-groups.sh \
  --bootstrap-server "$BS" \
  --describe \
  --group "$GROUP"
```

Example:

```text
TOPIC  PARTITION  CURRENT-OFFSET  LOG-END-OFFSET  LAG
orders 0          5               8               3
orders 1          4               4               0
orders 2          6               7               1
```

Memorise:

```text
CURRENT-OFFSET
→ Next offset the group will consume

LOG-END-OFFSET
→ End of the partition

LAG
→ LOG-END-OFFSET - CURRENT-OFFSET
```

Total lag above:

```text
3 + 0 + 1 = 4
```

---

## Show active consumers and assignments

```bash
kafka kafka-consumer-groups.sh \
  --bootstrap-server "$BS" \
  --describe \
  --group "$GROUP" \
  --members \
  --verbose
```

Example:

```text
CONSUMER-A → orders(0,1)
CONSUMER-B → orders(2)
```

---

## Show group state

```bash
kafka kafka-consumer-groups.sh \
  --bootstrap-server "$BS" \
  --describe \
  --group "$GROUP" \
  --state
```

Common states:

```text
Stable
→ Consumers are operating normally

PreparingRebalance
→ Kafka is redistributing partitions

Empty
→ Group exists but has no active consumers
```

Apache’s consumer-group CLI supports listing groups, viewing lag, inspecting members and assignments, and viewing group state. ([Apache Kafka](https://kafka.apache.org/43/operations/basic-kafka-operations/?utm_source=chatgpt.com 'Basic Kafka Operations'))

---

## Consumer group rules

```text
Same group ID
→ Consumers share partitions
→ One partition belongs to one active consumer

Different group IDs
→ Each group reads the topic independently

More consumers than partitions
→ Extra consumers remain idle
```

Example with three partitions:

```text
3 partitions + 2 consumers
→ Consumers share the three partitions

3 partitions + 3 consumers
→ One partition each

3 partitions + 4 consumers
→ One consumer is idle
```

# 5. Reset Consumer Group Offsets

Offset reset changes where a group resumes.

It does not delete Kafka records.

## Mandatory process

```text
1. Stop every consumer in the group
2. Preview the reset
3. Execute the reset
4. Verify the offsets
5. Restart the consumer
```

Kafka requires the group to be inactive before resetting offsets. Without `--execute`, the reset command previews the proposed offsets. ([Apache Kafka](https://kafka.apache.org/43/operations/basic-kafka-operations/?utm_source=chatgpt.com 'Basic Kafka Operations'))

---

## Reset to earliest: replay everything

Preview:

```bash
kafka kafka-consumer-groups.sh \
  --bootstrap-server "$BS" \
  --group "$GROUP" \
  --topic "$TOPIC" \
  --reset-offsets \
  --to-earliest
```

Execute:

```bash
kafka kafka-consumer-groups.sh \
  --bootstrap-server "$BS" \
  --group "$GROUP" \
  --topic "$TOPIC" \
  --reset-offsets \
  --to-earliest \
  --execute
```

Meaning:

```text
Replay all records still retained by Kafka
```

---

## Reset to latest: skip existing messages

Preview:

```bash
kafka kafka-consumer-groups.sh \
  --bootstrap-server "$BS" \
  --group "$GROUP" \
  --topic "$TOPIC" \
  --reset-offsets \
  --to-latest
```

Execute:

```bash
kafka kafka-consumer-groups.sh \
  --bootstrap-server "$BS" \
  --group "$GROUP" \
  --topic "$TOPIC" \
  --reset-offsets \
  --to-latest \
  --execute
```

Meaning:

```text
Skip existing records
Consume only records produced afterward
```

---

## Shift backwards: replay recent records

Replay the previous two offsets per partition:

```bash
kafka kafka-consumer-groups.sh \
  --bootstrap-server "$BS" \
  --group "$GROUP" \
  --topic "$TOPIC" \
  --reset-offsets \
  --shift-by -2
```

Execute:

```bash
kafka kafka-consumer-groups.sh \
  --bootstrap-server "$BS" \
  --group "$GROUP" \
  --topic "$TOPIC" \
  --reset-offsets \
  --shift-by -2 \
  --execute
```

Meaning:

```text
-2 → move backwards and replay
+2 → move forwards and skip
```

The shift is applied to every selected partition.

---

## Reset to a specific offset

```bash
kafka kafka-consumer-groups.sh \
  --bootstrap-server "$BS" \
  --group "$GROUP" \
  --topic "$TOPIC" \
  --reset-offsets \
  --to-offset 5
```

Execute:

```bash
kafka kafka-consumer-groups.sh \
  --bootstrap-server "$BS" \
  --group "$GROUP" \
  --topic "$TOPIC" \
  --reset-offsets \
  --to-offset 5 \
  --execute
```

Every selected partition is moved to offset `5`.

Remember:

```text
Partition 0 offset 5
≠
Partition 1 offset 5
```

---

## Verify after reset

```bash
kafka kafka-consumer-groups.sh \
  --bootstrap-server "$BS" \
  --describe \
  --group "$GROUP"
```

Restart normally:

```bash
kafka kafka-console-consumer.sh \
  --bootstrap-server "$BS" \
  --topic "$TOPIC" \
  --group "$GROUP"
```

Do not add `--from-beginning`; the reset already changed the committed offsets.

# Final rules to memorise

```text
Topic
→ Collection of partitioned records

Partition
→ Ordering boundary

Each producer input line
→ One Kafka record

Same key
→ Normally same partition

No named consumer group
→ Useful for inspection

Named consumer group
→ Saves committed offsets

Same group
→ Consumers share partitions

Different groups
→ Each group reads independently

CURRENT-OFFSET
→ Next offset to consume

LAG
→ Records waiting to be processed

--from-beginning
→ Used when no committed offset exists

--to-earliest
→ Replay retained records

--to-latest
→ Skip existing records

--shift-by -N
→ Replay recent records

Offset reset
→ Stop group, preview, execute, verify
```
