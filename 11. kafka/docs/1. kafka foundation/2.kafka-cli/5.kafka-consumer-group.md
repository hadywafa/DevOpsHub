# Kafka CLI — Consumer Groups Only

A **consumer group** represents one logical application consuming a topic.

```text
Topic: orders — 3 partitions

Consumer group: orders-service
├── Consumer 1 → Partition 0 and 1
└── Consumer 2 → Partition 2
```

## Core rule

```text
Same consumer group
→ Consumers divide the partitions.

Different consumer groups
→ Each group reads all records independently.
```

Within one group, a partition is assigned to only one active consumer at a time.

---

## 1. Create a consumer group

There is no separate “create group” command.

A group is created when a consumer starts with `--group`:

```bash
docker compose exec kafka-1 \
  /opt/kafka/bin/kafka-console-consumer.sh \
  --bootstrap-server kafka-1:19092 \
  --topic orders \
  --group orders-service \
  --from-beginning
```

Here:

```text
orders       = topic
orders-service = consumer group
```

Kafka stores the group’s committed offsets internally in:

```text
__consumer_offsets
```

---

## 2. List consumer groups

```bash
docker compose exec kafka-1 \
  /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server kafka-1:19092 \
  --list
```

Example:

```text
orders-service
payment-service
analytics-service
```

Notice the tool difference:

```text
kafka-console-consumer.sh
→ Consumes records

kafka-consumer-groups.sh
→ Manages and inspects consumer groups
```

## 3. Describe a consumer group

```bash
docker compose exec kafka-1 \
  /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server kafka-1:19092 \
  --describe \
  --group orders-service
```

Example output:

```text
GROUP           TOPIC   PARTITION  CURRENT-OFFSET  LOG-END-OFFSET  LAG
orders-service  orders  0          10              15              5
orders-service  orders  1          8               8               0
orders-service  orders  2          12              14              2
```

Apache’s consumer-group tool uses this output to show each group’s committed position and how far it is behind the partition log. ([Apache Kafka](https://kafka.apache.org/43/operations/basic-kafka-operations/?utm_source=chatgpt.com "Basic Kafka Operations | Apache Kafka"))

### `CURRENT-OFFSET`

```text
CURRENT-OFFSET = 10
```

This is the **next offset the group should consume**.

Therefore, offsets `0` through `9` are considered processed.

### `LOG-END-OFFSET`

```text
LOG-END-OFFSET = 15
```

This is the end of the partition. Existing records are up to offset `14`; the next produced record receives offset `15`.

### `LAG`

```text
LAG = LOG-END-OFFSET - CURRENT-OFFSET
```

Example:

```text
15 - 10 = 5 records behind
```

Total group lag in the example:

```text
Partition 0 = 5
Partition 1 = 0
Partition 2 = 2

Total lag = 7
```

### Memorise

```text
CURRENT-OFFSET
→ Next record the group will consume

LOG-END-OFFSET
→ End of the partition

LAG
→ Records waiting to be processed
```

## 4. Show active consumers

While consumers are running:

```bash
docker compose exec kafka-1 \
  /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server kafka-1:19092 \
  --describe \
  --group orders-service \
  --members
```

Example:

```text
CONSUMER-ID      HOST          CLIENT-ID          #PARTITIONS
consumer-a       /172.20.0.4   console-consumer   2
consumer-b       /172.20.0.5   console-consumer   1
```

This means:

```text
Consumer A owns 2 partitions
Consumer B owns 1 partition
```

## 5. Show exact partition assignments

```bash
docker compose exec kafka-1 \
  /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server kafka-1:19092 \
  --describe \
  --group orders-service \
  --members \
  --verbose
```

Example:

```text
CONSUMER-ID  #PARTITIONS  ASSIGNMENT
consumer-a   2            orders(0,1)
consumer-b   1            orders(2)
```

This is the best command for seeing exactly which consumer owns which partitions. ([Apache Kafka](https://kafka.apache.org/43/operations/basic-kafka-operations/?utm_source=chatgpt.com "Basic Kafka Operations | Apache Kafka"))

## 6. Show group state

```bash
docker compose exec kafka-1 \
  /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server kafka-1:19092 \
  --describe \
  --group orders-service \
  --state
```

Example:

```text
COORDINATOR       ASSIGNMENT-STRATEGY  STATE   #MEMBERS
kafka-2:19092     range                Stable  2
```

Important fields:

```text
COORDINATOR
→ Broker managing the consumer group

STATE
→ Current group status

#MEMBERS
→ Number of active consumers
```

Common states:

```text
Stable
→ Consumers are running normally.

PreparingRebalance / Assigning
→ Kafka is redistributing partitions.

Empty
→ Group exists, but no consumers are running.
```

---

## 7. More consumers than partitions

Suppose:

```text
Topic partitions = 3
Consumers in same group = 4
```

Result:

```text
Consumer 1 → Partition 0
Consumer 2 → Partition 1
Consumer 3 → Partition 2
Consumer 4 → Idle
```

Rule:

```text
Maximum useful active consumers in one group
= number of topic partitions
```

---

## 8. Delete a consumer group

First stop all consumers using the group, then run:

```bash
docker compose exec kafka-1 \
  /opt/kafka/bin/kafka-consumer-groups.sh \
  --bootstrap-server kafka-1:19092 \
  --delete \
  --group orders-service
```

Deleting the group removes its committed offsets and group metadata.

It does **not** delete:

```text
Topics
Partitions
Kafka records
```

Kafka only permits manual group deletion when the group has no active members. ([Apache Kafka](https://kafka.apache.org/43/operations/basic-kafka-operations/?utm_source=chatgpt.com "Basic Kafka Operations | Apache Kafka"))

# Commands to memorise

```bash
# List groups
kafka-consumer-groups.sh --bootstrap-server kafka-1:19092 --list

# Show offsets and lag
kafka-consumer-groups.sh --bootstrap-server kafka-1:19092 \
  --describe --group orders-service

# Show members
kafka-consumer-groups.sh --bootstrap-server kafka-1:19092 \
  --describe --group orders-service --members

# Show exact partition assignments
kafka-consumer-groups.sh --bootstrap-server kafka-1:19092 \
  --describe --group orders-service --members --verbose

# Show state
kafka-consumer-groups.sh --bootstrap-server kafka-1:19092 \
  --describe --group orders-service --state
```

## Final memory rule

```text
Consumer group = one logical application

Same group
→ Share partitions

Different groups
→ Read independently

Lag
→ How far the application is behind

Committed offset
→ Where the group resumes
```
