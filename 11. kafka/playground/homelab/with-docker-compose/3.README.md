# Three-node Apache Kafka KRaft lab with Kafbat UI

## Components

- Apache Kafka 4.3.1
- Three combined broker/controller KRaft nodes
- Kafbat UI v1.5.0
- Replication factor 3
- Minimum in-sync replicas 2
- Persistent Docker volumes
- Separate internal, external and controller listeners
- No ZooKeeper

This setup is intended for local learning, integration testing and failover labs.
It uses PLAINTEXT networking and is not an internet-facing production deployment.

## Requirements

- Docker Engine 20.10.4 or newer
- Docker Compose v2 (`docker compose`)
- At least 4 GB free RAM; 6 GB is more comfortable
- Ports 29092, 39092, 49092 and 8080 available

## Start

```bash
chmod +x start.sh stop.sh reset.sh scripts/*.sh
./start.sh
```

The first run generates a unique KRaft cluster ID and writes it to `.env`.

Open:

- Kafbat UI: http://localhost:8080
- Host bootstrap servers: `localhost:29092,localhost:39092,localhost:49092`
- Docker-network bootstrap servers: `kafka-1:19092,kafka-2:19092,kafka-3:19092`

## Verify

```bash
./scripts/status.sh
```

You should see three Kafka containers, one KRaft leader, two quorum followers and
all three brokers reachable.

## Create a demo topic

```bash
./scripts/create-demo-topic.sh
```

Defaults:

- Topic: `orders`
- Partitions: `6`
- Replication factor: `3`
- `min.insync.replicas=2`

Custom topic and partition count:

```bash
./scripts/create-demo-topic.sh payments 9
```

## Produce records

```bash
./scripts/produce.sh orders
```

The producer uses `acks=all` so the `min.insync.replicas=2` rule is meaningful.

## Consume records

```bash
./scripts/consume.sh orders orders-demo-group
```

The output includes partition and offset.

## Inspect the topic and consumer groups

```bash
./scripts/describe-topic.sh orders
./scripts/consumer-groups.sh
```

## Failover test

1. Create the topic and start a producer.

```bash
./scripts/create-demo-topic.sh orders 6
./scripts/produce.sh orders
```

2. In another terminal, stop one node.

```bash
docker compose stop kafka-1
```

3. Wait several seconds, then inspect replica leadership and ISR.

```bash
./scripts/describe-topic.sh orders
./scripts/status.sh
```

Writes with `acks=all` should continue because two in-sync replicas remain.

4. Restart the node.

```bash
docker compose start kafka-1
```

5. Wait until it rejoins ISR and verify again.

```bash
./scripts/describe-topic.sh orders
```

### Why not stop two brokers?

With replication factor 3 and `min.insync.replicas=2`, only one broker would
remain. Producers using `acks=all` should then fail rather than acknowledge a
write that exists on only one replica. This is the expected durability behavior.

## Useful commands

```bash
# Logs
docker compose logs -f kafka-1 kafka-2 kafka-3

docker compose logs -f kafbat-ui

# Restart one broker
docker compose restart kafka-2

# List topics
docker compose exec kafka-1 \
  /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server kafka-1:19092 \
  --list

# Show KRaft quorum
docker compose exec kafka-1 \
  /opt/kafka/bin/kafka-metadata-quorum.sh \
  --bootstrap-server kafka-1:19092 \
  describe --status
```

## Stop without deleting data

```bash
./stop.sh
```

Start again with:

```bash
./start.sh
```

## Delete all Kafka data and rebuild

```bash
./reset.sh
./start.sh
```

Do not change `KAFKA_CLUSTER_ID` while reusing existing Kafka data volumes. The
cluster ID stored on disk must match the ID supplied to all three nodes.

## Connect from another machine

Edit `.env`:

```dotenv
KAFKA_BIND_ADDRESS=0.0.0.0
KAFKA_EXTERNAL_HOST=your-server-fqdn-or-ip
KAFKA_UI_BIND_ADDRESS=0.0.0.0
```

Then recreate the containers:

```bash
docker compose up -d --force-recreate
```

Allow TCP ports 29092, 39092 and 49092 through the firewall. Do not expose this
PLAINTEXT lab to the public internet. Use TLS/SASL and UI authentication for any
shared or production-like environment.

## Listener model

- `INTERNAL`: broker-to-broker traffic and Docker-network clients such as Kafbat
- `EXTERNAL`: applications running on the Docker host or a configured remote host
- `CONTROLLER`: KRaft metadata quorum traffic only

Kafka clients must be able to resolve and reach every address returned in
`advertised.listeners`, not only the first bootstrap address.

## Production distinction

This lab uses combined nodes because it is compact and useful for learning.
For a critical production platform, use dedicated KRaft controllers, dedicated
brokers, TLS/SASL, ACLs, monitoring, backups, capacity planning and failure-domain
separation across hosts or availability zones.
